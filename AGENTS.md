# AGENTS.md

This file is for AI coding agents (Claude Code, Codex, Cursor, or any other tool) working in
this repository. It is the only file in this repository where tool names like these may
appear: the rest of the repository speaks in my own first-person voice, and the research
itself is floflo777's; this repository is a maintained mirror of
`floflo777/unsolved-crypto-puzzles`.

## 1. What this repository is

`unsolved-crypto-puzzles` catalogues public crypto treasure-hunt puzzles whose prize is still
funded: an author locks BTC, ETH, AR or a token behind a riddle, publishes the escrow address,
and invites the public to solve it and take the coins. Solved and swept puzzles are removed;
the per-address proof for every remaining escrow is in `verification/BALANCES.md`. Each puzzle has a folder with a `README.md` (the full story) and a
`puzzle.json` (the machine-readable manifest). The root `puzzles.json`, generated by
`tools/build_index.py`, concatenates every folder's manifest into one index. Start there if
you need to pick a target; start at the folder's `README.md` if you already have one.

## 2. Workflow for one puzzle

1. Read `<folder>/README.md` in full.
2. Read `<folder>/analysis/tested.md` and `<folder>/analysis/leads.md` if they exist.
3. Run `python3 tools/check_escrows.py --slug <slug>`. Do not proceed if the escrow is not
   funded and unspent.
4. Run `python3 <folder>/tools/oracle.py --selftest` if the folder has an oracle. Do not
   search with an oracle that fails its self-test.
5. Only then propose a hypothesis or a candidate.

## 3. Rules

- The escrow state is the truth. Do not work on a puzzle whose escrow is unfunded or swept;
  `tools/check_escrows.py` tells you which.
- Do not repeat any row of `analysis/tested.md`. If you test something new, extend it with a
  new row: count, method, witness, date.
- A candidate is a solution only on an exact match reported by the oracle. Checksum validity,
  "plausible" plaintext, and near misses are not solutions.
- A negative without a witness (a known-good input pushed through the same code and re-found)
  is not a negative. Call it "uncertified" and say so.
- Before any loop, write down N (the size of the space), D (your measured rate), and
  t = N / D. If t is above two hours, look for a constraint that shrinks N instead of asking
  for more compute.
- Never broadcast a transaction. Never post private key material or a seed publicly. Hand key
  material to the human running you; the human sweeps the funds first and announces after.
- Do not add copyrighted material to the repository: no book text, no transcripts, no full
  articles, no wordlists. Link to the source instead.
- Report back as a delta: what you tested, with counts; what remains; what you believed that
  turned out to be wrong.

## 4. Starter prompt

Paste this, filling in `<slug>` and `<folder>`:

```
You are working on the public repository unsolved-crypto-puzzles. Target puzzle: <slug>.
1. Read <folder>/README.md entirely, then <folder>/analysis/tested.md and analysis/leads.md.
2. Run: python3 tools/check_escrows.py --slug <slug>. If the escrow is not funded and unspent, stop and report.
3. Run: python3 <folder>/tools/oracle.py --selftest. If it fails, fix the environment or stop; do not search with an uncertified oracle.
4. Do not repeat anything listed in tested.md. Pick the highest-ranked lead you can act on, or propose a new hypothesis with its size N, your measured rate D, and t = N/D.
5. Every candidate goes through the oracle. A solution is an exact MATCH only.
6. Any negative you report must state count, method, witness (a known-good input re-found through the same code), rate, and date; otherwise label it uncertified.
7. Never broadcast a transaction and never print private keys or seeds outside the local machine. If you find a MATCH, stop and give the human the exact answer and the derivation.
8. Finish with a delta: tested (with numbers), what remains, corrections to the README if you found an error, one line per lead you would rank differently and why.
```

## 5. How to run the tools

Install once, from the repository root:

```bash
python3 -m pip install -r tools/requirements.txt
```

Three commands you will use most:

```bash
python3 tools/check_escrows.py --slug <slug>          # confirm the escrow is still funded and unspent
python3 tools/derive.py bip39 "<12 or 24 words>" --path bip84 --target <address>   # test a candidate
python3 tools/validate.py --folder <slug>              # check a folder against the QA rules before proposing changes
```

`tools/build_index.py` regenerates `puzzles.json` and the generated tables in the README
files; run it with `--check` to see whether the index is stale without writing anything.
